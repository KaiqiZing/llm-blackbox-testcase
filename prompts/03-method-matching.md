# Prompt 3 · 黑盒方法匹配

> 输入：Prompt 2 的特征画像。产出：方法矩阵 JSON（供机械校验）+ Markdown 表格（人读版）。
> **执行前必须注入 `references/mapping-matrix.md` 全文（或 `system-constraint.md`）作为系统约束。**

```text
基于特征画像，为每个测试点匹配黑盒测试方法。映射矩阵已在系统约束中给出（18 类特征形态 → 主方法 + 辅助方法），必须严格遵守，不得凭习惯选择。

【判断范式（Few-Shot）】
a. 连续输入/单值边界 → 等价类划分、边界值分析（年龄、金额范围）
b. 离散条件布尔组合、分支互斥 → 判定表法、因果图法（风控多重开关、计费折扣叠加）
c. 多参数/多配置组合爆炸 → 正交试验设计、成对测试 Pairwise（多设备机型兼容、多种筛选条件）
d. 状态机/生命周期 → 状态迁移测试（订单流转）
e. 端到端业务流程 → 场景法（开户到交收）
f. 金额/费率计算 → 边界值分析（佣金分界点）
g. 动态阈值 → 边界值分析·动态边界（价格笼子，多组基准值）
h. 时序/并发/幂等 → 场景法、错误推测法（重复提交、竞态）

【要求】
1. 每行必须写「选择理由」，依据只能是特征信号；
   反面示例：因为这是常用的方法 / 这样比较保险；
   正面示例：条件数 4、结果数 1、条件间存在互斥约束，判定表覆盖全组合，因果图先化简约束。
2. 给出主方法与辅助方法，说明各自负责覆盖什么（分工不能重复）；
3. 写出覆盖目标与退出标准；
4. 特征跨多类时允许组合 2~3 个方法，必须说明分工边界；
5. 「需降维」为 true 的测试点，必须写明：组合总数、降维方法、降维后数量、被舍弃的组合与风险判断。

【输出 1】方法矩阵 JSON（**必须产出**，供 `scripts/validate-output.py --stage method` 机械校验）：
[{
  "需求点": "R1",
  "测试点": "委托价格的有效申报范围",
  "被测对象特征": "F1 连续数值区间",
  "推荐黑盒测试方法": "等价类划分（主）+ 边界值分析（辅）",
  "方法分工": "等价类打底分有效/无效域；边界值在上点/内点/离点加密，二者不覆盖同一批数据",
  "选择理由": "依据特征信号：单个连续输入、有明确上下界、结果非通过即拒绝（F1）",
  "覆盖目标与退出标准": "有效域 2 类 + 无效域 3 类全覆盖，边界三层（上点/内点/离点）齐备即退出"
}]

【输出 2】人读版 Markdown 表格（列固定，供报告直接采用）：
| 需求点 | 拆分测试点 | 被测对象特征 | 推荐黑盒测试方法（主+辅） | 选择理由 | 覆盖目标与退出标准 |
  注意：JSON 的 `测试点` 对应表格的「拆分测试点」列，字段名以 JSON 为准（校验脚本按 JSON 字段名解析）。
```

## 失败信号

- 全部测试点推荐"等价类 + 边界值" → 触发质量闸门 ③，打回。
- 选择理由含"常用/通常/确保覆盖/比较保险" → 触发质量闸门 ④，打回。
- 状态机特征用了判定表、组合爆炸却全量罗列 → 映射错误，对照矩阵重选。
