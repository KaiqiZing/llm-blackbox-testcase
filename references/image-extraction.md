# 图片需求源提取规范

> **本文件解决的问题**：需求文档里的图（原型图、界面截图、流程图、状态图、字段表截图）承载了大量
> **正文没写、但必须测**的信息。当正文只写一句「字段如图所示」时，图就是**唯一**需求源。
>
> 不走本规范，模型只能看到「如图所示」四个字，产出会出现三类系统性缺口：
> ① 图里的字段/按钮/列名整个漏掉；② 图里的信息被当正文的附属品，不生成独立需求点；
> ③ 图与正文冲突时不报错，静默取其一。
>
> **本规范是流程性规范，不是建议**。SKILL.md 第 0 步必须先跑完本规范，才能进第 1 步拆解。

---

## 一、素材取图方法（按载体格式）

### 1.1 统一入口：`scripts/extract_images.py`

```bash
python3 scripts/extract_images.py <素材文件> [--out <输出目录>]
```

产出：`<输出目录>/images/`（图片原文件）+ `<输出目录>/manifest.json`（图片清单）。
**禁止手写解包脚本**——手写必然漏掉空 basename、嵌套 media 目录、同图多格式这些边角。

### 1.2 各载体格式的取图路径

| 载体格式 | 取图位置 | 说明 |
|---|---|---|
| `.docx` / `.docm` / `.dotx` | zip 内 `word/media/*` | 图片按 `image1.png`、`image2.jpeg`… 顺序编号，编号即正文出现顺序（**大前提，但需交叉验证，见 §2.3**） |
| `.wps` | zip 内 `word/media/*` | WPS 保存的 docx 兼容格式，路径同上；若解包失败，另试 `word/media` 大小写变体与 `Object` 目录 |
| `.pptx` / `.ppsx` / `.potx` | zip 内 `ppt/media/*` | 每页图的归属需结合 `ppt/slides/_rels/slideN.xml.rels` 建立「页号 → 图」映射 |
| `.xlsx` / `.xlsm` | zip 内 `xl/media/*` | 用 `xl/drawings/drawingN.xml` 的锚点定位图落在哪个工作表/单元格 |
| `.pdf` | 需按页渲染（`pdftoppm` / `pymupdf`） | 无第三方库时降级：**不抽图，改为「按页登记」**——把每一页登记为一个待人工补录的素材单元，并在 `gaps[]` 里标 `图片未能自动提取` |
| `.md` | 相对路径 `![](xxx.png)` | 相对 md 文件所在目录解析；路径含中文/空格时按原样保留，不要 URL 解码 |
| 直接贴图（对话中粘贴） | 已在上下文中 | 无需解包，直接按「出现顺序」编号，并在 `来源` 里标注 `对话粘贴` |
| 剪贴板/桌面散图 | 目录扫描 | 按文件名自然序 + 修改时间排序编号，**必须**在 `gaps[]` 标注「无正文锚点，归属待确认」 |

### 1.3 降级原则

任一步骤失败，**不得静默跳过**。降级动作固定为两条：

1. 在 `asset-inventory.json` 的 `gaps[]` 里记一条：`{"类型": "提取失败", "位置": "...", "原因": "..."}`；
2. 在最终报告里显式列出「本次未能自动提取的素材」，并说明该部分需求点的证据强度降级为 `[待确认]`。

## 二、图片编号与「文本 → 图片」锚点映射

### 2.1 图片编号规则（`img-N`）

- 编号 = 在 `manifest.json` 中的自然序号，从 1 开始，格式 `img-1`、`img-2`…
- **编号一旦分配，全程不变**：后续所有 JSON 产物（asset-inventory / step1 / step2 / step3 / step4）引用同一张图时必须用同一编号。
- 图片重名、格式不同（同内容的 `.png` 与 `.jpeg`）时合并为一张，保留字节数较大的，并在 `说明` 里记 `合并自 imageN.png/imageM.jpeg`。
- 尺寸小于 16×16 的图（图标、分隔线、装饰点）默认**不编号**，但要在 `manifest.json` 里标 `排除: 尺寸过小`，避免后续误判为「漏图」。
- **编号顺序 = 文档正文出现顺序**（docx / pptx 由脚本解析 OOXML 确定），不是 media 文件名的字典序。
- `--also-text` 会额外导出正文到 `<out>/<素材名>-正文.txt`，图片位置用 `[IMG img-N]` 标记；
  同时给每张图在 manifest 里写入 `前一正文段落` / `后一正文段落`（pptx 为 `所在位置: 第 N 页幻灯片`）。
  **锚定「如图所示」时优先用这两个字段**，其次才是 `顺序提示`——后者只是弱证据。

### 2.2 引用措辞识别（文本侧锚点）

在正文段落里搜索以下措辞，命中即说明**该段落的完整信息依赖某张图**：

| 类别 | 触发措辞（正则） |
|---|---|
| 显式指向 | `如图\s*\d*` / `如下图` / `见图\s*\d*` / `如下图所示` / `如下表` / `见下表` / `上图` / `下图` |
| 隐含指向 | `如图所示` / `如下图` / `见下图` / `如左图所示` / `如图 1 所示` / `图 3-1 所示` / `按下图` / `如下截图` / `界面如下` / `参考下图` / `参照下列图` |
| 无措辞但强依赖 | 段落以「字段」「按钮」「列」「查询条件」「操作」为主语且后接冒号列举，但列举项只有 1~2 个（**列举必然不全**，说明完整清单在图里） |

**关键判定**：只要段落命中「显式/隐含指向」，该段落就是 `image_refs[]` 的一条记录，
**必须**解析出它指向哪张图；解析不出，直接进 `gaps[]`，等级为**硬缺口**（不是告警）。

### 2.3 锚点定位的三条依据（按可信度排序）

1. **段落顺序对齐（最可靠）**：正文段落出现顺序 ≈ media 内图片编号顺序。第 k 个含图引用的段落，大概率指向 `img-k`。
2. **语义匹配（交叉验证）**：段落里的界面名/字段名/按钮名，与图片提取出的元素（§三）做交集，命中越高越可信。
3. **上下文相邻（辅助）**：同一小节内的引用措辞指向同一张图；跨小节的引用措辞指向紧邻该小节的图。

**冲突处置**：依据 1 与依据 2 结论不一致时，**以依据 2 为准**（语义匹配可信度高于顺序），
但在 `asset-inventory.json` 的 `gaps[]` 里记一条 `{"类型": "锚点存疑", ...}` 供人工复核。
**不得**因依据冲突而放弃锚定——放弃就等于丢图。

### 2.4 一张图被多处引用 / 一处引用多张图

- 一图多引：`image_refs[]` 允许多条记录指向同一 `图片编号`，正常，不重复登记图片。
- 一引多图（如「如下图 1、图 2 所示」）：拆成两条 `image_refs[]` 记录，各自独立锚定。
- 段落引用了图，但该段落本身又是另一图的说明文字：两条引用都保留，**不做链式推断**。

## 三、图片必提元素清单（8 类）

对每张已编号的图，逐类清点。**图里能看见的元素，只要属于下列 8 类，全部提取**——
提取结果直接构成后续需求点的原始证据，不允许概括为「界面上有若干按钮」。

| # | 类别 | 要提取什么 | 漏了会怎样 |
|---|---|---|---|
| 1 | **字段名 + 必输标记** | 每个字段的完整名称、是否带 `*`（必输）、控件类型（输入框/下拉/日期/文件）、默认值、占位提示 | 必输性判反，产生一整批错误用例；漏字段等于漏需求点 |
| 2 | **按钮 + 位置** | 按钮文案、所在区域（顶部操作区 / 行操作列 / 弹窗底部）、样式（主按钮/次按钮） | **状态机分叉整个丢掉**（典型：「取消/保存/直接上架」三分叉只测了保存） |
| 3 | **列表列名** | 列标题全称、列顺序、是否有排序箭头 | 列表展示类需求点全丢；排序/列宽类用例没依据 |
| 4 | **查询条件** | 查询区每个条件的名称与控件类型（含日期区间「开始-结束」）、是否有重置/查询按钮 | 查询功能测试点无依据，条件组合用不到 |
| 5 | **分页参数** | 总条数文案、每页条数选项、页数展示、跳转控件（`GO`/页码） | 分页类边界值没依据（「1000 条/页」这种上限就藏在图里） |
| 6 | **状态列 / 状态标识** | 状态列的取值枚举、颜色/标签样式、状态与 tab 的对应关系 | **状态迁移测试的合法状态集不完整**，非法迁移用例造不出来 |
| 7 | **弹窗 / 提示文案** | 弹窗标题、正文、按钮、Toast 文案（含成功/失败） | 质量闸门⑧要求的「具体文案」写不出来，只能写「提示错误」被打回 |
| 8 | **校验提示 / 错误态** | 字段下方的红字提示、错误图标、必填未填时的样式变化 | 无效域用例的预期结果没法定量描述 |

**补充要求**：
- 提取时**保留原文用词**（含标点与全角符号），不要改写成同义词——「直接上架」不能写成「立即上架」。
- 图里**看不清**的元素，写 `[图不清] 疑似：xxx`，进 `gaps[]`，**不许猜**。
- 表格类图（字段说明表）：按行提取，每行一个字段，**不要**并成一句话。

## 四、提取结果如何回填需求点

### 4.1 回填路径总览

```
素材文件
  └─ extract_images.py ─→ images/ + manifest.json
                              │
                              ▼
                    asset-inventory.json         （第 0 步产出）
                    ├─ assets[]      素材单元清单
                    ├─ image_refs[]  文本→图片 锚点映射
                    └─ gaps[]        缺口与存疑
                              │
                              ▼
                    step1_require.json           （Prompt 1 产出）
                    └─ 原文依据 拆成两个字段：
                       ├─ 文本依据  引正文原句
                       └─ 图片依据  {图号, 界面名, 提取元素}  ← 本规范的核心产物
```

### 4.2 `原文依据` 字段拆解（Prompt 1 契约变更）

原来的单一字段 `原文依据` 拆为两个：

```json
{
  "id": "R1",
  "需求点": "...",
  "类型": "功能",
  "文本依据": "正文原句；无正文则填 \"\" 并在图片依据里说明",
  "图片依据": [
    {
      "图号": "img-2",
      "界面名": "新增英文研报",
      "引用措辞": "b. 字段如图所示",
      "提取元素": [
        "字段：标题*（文本输入，必输）",
        "字段：摘要*（多行文本，必输）",
        "字段：分类*（下拉，7 项）",
        "字段：研究员*（多值，逗号分隔，必输）",
        "字段：文件*（文件选择，仅 PDF，≤100M）",
        "按钮：取消（弹窗底部，次按钮）",
        "按钮：保存（弹窗底部，主按钮）",
        "按钮：直接上架（弹窗底部，主按钮）"
      ]
    }
  ],
  "业务规则": "...",
  "验收标准": "...",
  "待确认": false
}
```

字段规则：
- `文本依据` 与 `图片依据` **至少一个非空**；两者都空 → 直接判为编造，硬性不通过。
- `图片依据` 为**数组**（一段需求可能锚定多张图）；无图则填 `[]`。
- `提取元素` 必须是 §3 八类清单的**逐条罗列**，不是概述。少于 2 条时脚本告警（疑似摘要有损）。
- **纯图需求点**（`文本依据` 为空）：`待确认` 可保持 `false`——图本身就是需求源，不算推断。
  但必须在 `验收标准` 里写清楚「依据图 img-N 的 X 元素」。

### 4.3 图与正文冲突的处理

冲突只有三种情形，处置方式固定：

| 情形 | 处置 |
|---|---|
| 正文与图**互补**（各写一半） | 合并为一条需求点，两个依据都保留 |
| 正文与图**矛盾**（如正文写「含批量」，图里只有单条按钮） | 拆为**两条**需求点，各自 `待确认: true`，并在 `gaps[]` 记 `{"类型": "图文冲突"}`；**禁止**替业务方拍板取其一 |
| 图有、正文完全没提 | 单独成需求点，`文本依据: ""`，标注「图片新增」；这是漏需求的高发区 |

## 五、失败信号（触发打回）

| 信号 | 说明 | 处置 |
|---|---|---|
| `image_refs[]` 为空，但正文含「如图所示」类措辞 | 锚点映射没做 | 打回第 0 步 |
| `图片依据[].提取元素` 少于 2 条 | 提取成了概述，未逐条清点 | 打回，按 §3 八类清单重提 |
| 提取元素里出现「若干」「一些」「等」 | 没有真正看图 | 打回 |
| 图片可见但未被任何需求点引用 | 可能漏需求（尤其状态机按钮、查询条件） | 进 `gaps[]` 人工复核，标注「有图无引用」 |
| 正文引用措辞指向 `img-N`，但 `img-N` 不存在于 manifest | 编号错乱 | 硬缺口，必须修 |
| 图里出现正文未提的按钮/状态取值，而 step1 未生成对应需求点 | 图 → 需求 的回填断了 | 打回第 0/1 步 |
| `gaps[]` 里有 `提取失败`，但报告未声明证据降级 | 静默降级 | 打回第 6 步交付 |

## 六、Few-Shot（回归样本：`英文研报运营.docx`）

> 该样本是理想测试集：**5 张图 + 5 处「如图所示」类引用 + 1 处图片独有按钮**。
> 下面演示完整的「取图 → 锚定 → 清点 → 回填」链路，生成时按此范式推理，不要照抄业务数字。

### 6.1 取图

```
$ extract_images.py 英文研报运营.docx --out ./assets
images/  image1.png 147973B  image2.png 63164B  image3.png 137605B
         image4.png 127649B  image5.png 131256B
manifest.json  →  5 张图全部编号 img-1 ~ img-5
```

**关键观察**：`image2.png` 字节数显著最小（63KB vs 其余 127~148KB）。
结合语义匹配（§2.3 依据 2）可判定它是一张**表单类截图**（内容少、无数据行），
对应正文提到的「新增」页面——**这类尺寸提示（字节明显偏离中位数）是锚点定位的强信号**，要主动利用。

### 6.2 锚定（正文措辞 → 图）

> 下表是**回归后修正过**的结果：如果只按「第 k 个引用 → img-k」的顺序对齐，
> 会把待上架列表锚到 img-4（顺序猜错）。**语义匹配（依据 2）把它纠正了回来**——
> 这正是 §2.3 规定「冲突时以语义匹配为准」的原因。

| 正文措辞 | 位置 | 指向 | 判定依据 |
|---|---|---|---|
| 「b. 字段如图所示」 | 新增小节 | `img-2` | 顺序对齐（新增小节 → 第 2 张图）+ 语义匹配（img-2 是五个必输字段的表单页，与「字段」吻合） |
| 「支持对新增保存待上架的英文研报删除(含批量)、编辑、上架(含批量)」 | 待上架小节 | `img-1` | 语义匹配：img-1 顶部按钮 [新增 上架 删除]、行操作列 [上架 编辑 删除 详情]，与「删除/编辑/上架(含批量)」逐词吻合 |
| 「支持已上架的英文研报下架（含批量）」 | 已上架小节 | `img-3` | 语义匹配：img-3 行操作列 [下架 复制地址 详情]、顶部 [下架] 按钮 |
| 排序规则「按最新操作时间倒序」 | 四个列表 | `img-1/img-3/img-4/img-5` | 四张列表图各含「最新操作时间」列，说明规则依附于每个列表界面 |
| 查询区描述（无措辞，仅列举「标题/摘要/分类」） | 四个列表 | `img-1/img-3/img-4/img-5` | **隐含指向**：列举只有 3 项，而图里有 6 项（含研究员、创建人、创建日期区间），属 §2.2「无措辞但强依赖」 |

**锚定验证中发现的真实图文差异**（回归的额外收获，进 `gaps[]` 人工复核）：

- img-4（已下架）行操作列只有 [详情]，无 编辑/删除/上架按钮；而正文 R10 说「已下架均可编辑」。
  → 记 `图文冲突` 一条：编辑入口可能在详情页内，需业务方确认入口位置。
- img-5（全部）行操作列只有 [详情]，与正文未提「全部 tab 不可直接操作」一致，
  → 记 `有图无引用`：这个取值约束正文没写，应补一条「图片新增」需求点。
- img-3 行操作列含 [复制地址]，img-1/img-4/img-5 均无 → 与正文 R8「复制链接仅已上架」**互相印证**，置信度高。

### 6.3 清点（`img-2` 新增页面）

按 §3 八类清单逐条提取：

```
1 字段名+必输：标题*（文本输入，placeholder 请输入） / 摘要*（文本输入，placeholder 请输入）
               / 分类*（下拉，请选择） / 研究员*（文本输入，placeholder 请输入）
               / 文件*（上传区「+ 英文研报」）
2 按钮+位置：  取消（页面底部，次按钮） / 保存（页面底部，次按钮） / 直接上架（页面底部，主按钮，蓝色）
3 列表列名：   —（非列表界面）
4 查询条件：   —（非查询界面）
5 分页参数：   —（非列表界面）
6 状态列：     —（非列表界面）
7 弹窗/页面文案：页面标题「← 英文研报新增」（带返回箭头，说明是独立页面而非弹窗）；
               顶栏菜单：用户运营/内容运营/业务运营；左侧菜单：内容中心-内容管理-海外机构用户管理-英文研报管理
8 校验提示：   截图中无（空表单未提交），[图不清] 需人工补录或实测确认
```

**关键判定示范**：第 7 类里「← 返回箭头 + 页面标题」看似装饰信息，
实际它决定了测试用例的前置条件写法（「进入英文研报新增页面」而非「打开新增弹窗」），
也决定了关闭方式用例（浏览器返回 vs 弹窗 ×）。
**第 5 类在 img-3/4/5 列表页里提取出「共1203条 500条/页 1/3 GO」**——
