# Prompt 4 · 用例生成与覆盖自检

> 输入：Prompt 3 的方法矩阵。产出：可执行用例集 JSON + 自检报告。
> 需要展开到可执行用例时才跑这段；只要映射表时可跳过。

```text
基于方法矩阵，为每个测试点生成可执行用例，并做覆盖度自检。

【用例字段（固定）】
用例ID / 需求点 / 测试点 / 方法归属 / 用例类型(有效|无效|边界·上点|边界·内点|边界·离点|异常) /
前置条件 / 输入数据（具体到值） / 操作步骤 / 预期结果（唯一可判定） / 优先级 / 是否可自动化

【生成约束】
1. 输入数据必须具体：写 "10.21" 而不是 "超出范围的价格"；
2. 预期结果必须唯一可判定：写 "系统拒单并提示『委托价格超出有效申报范围』，委托不进入交易所"，
   禁止写 "系统提示错误 / 应该正常 / 符合预期"；
3. 无效等价类 + 边界离点 + 异常流的用例占比不得低于 30%；
4. 判定表类测试点：每个条件组合至少 1 条用例，并单独列出规则冲突检测用例；
5. 正交/配对类测试点：注明该用例覆盖了哪些参数对，并给出两两覆盖率；
6. 状态迁移类测试点：覆盖所有合法迁移 + 至少 3 条典型非法迁移（绕过前端构造）；
7. 边界类测试点：必须同时存在上点、内点、离点三层；
8. **测试边界（第 1 步第 4 问的答案）**：非法迁移防护 / 越权矩阵 / 跨系统推送类用例，按边界答案三选一写法——
   可直调接口 → 具体请求 + 预期响应/状态码，`是否可自动化: 是`；
   只有 UI → 改写为「UI 层入口缺失断言」，并在自检报告 d) 里声明接口层未覆盖；
   未知 → 标 [待确认] 且不进执行集（不计入可执行用例数）。

【输出 1】用例集 JSON（**必须产出**，供 `scripts/validate-output.py --stage case` 机械校验）：
[{
  "用例ID": "TC-R1-01",
  "需求点": "R1",
  "测试点": "委托价格的有效申报范围",
  "方法归属": "边界值分析·离点",
  "用例类型": "无效",
  "前置条件": "已登录、账户状态正常",
  "输入数据": "100000.00",
  "操作步骤": "1) 进入委托页 2) 价格填 100000.00 3) 点击买入",
  "预期结果": "系统拒单并提示『委托价格超出有效申报范围』，委托不进入交易所",
  "优先级": "高",
  "是否可自动化": "是"
}]
  用例类型取值固定为：有效 / 无效 / 边界·上点 / 边界·内点 / 边界·离点 / 异常。

【输出 2】自检报告（Markdown，人读版），逐条回答并给出量化结果：
a) 需求覆盖率 = 已覆盖需求点 / 需求点总数
b) 方法覆盖率 = 实际用到的方法数 / 方法矩阵中推荐的方法数
c) 18 类特征中哪几类有画像但没有对应用例？是否为遗漏？列出补救用例
d) 组合降维后损失了哪些组合？这些组合的风险是否可接受？
e) 还有哪些 [待确认] 项会直接阻塞用例执行？
```

## 失败信号

- 预期结果出现"应该正常/提示错误/符合预期" → 触发质量闸门 ⑧，打回。
- 无效域用例占比 < 30% → 触发质量闸门 ⑦，打回补充。
- 用例数据写"任意值/合法值" → 不可执行，打回。
