# 黑盒测试方法目录（完整版）

> 14 种方法。每种给出：定位、适用条件、执行步骤、产出物、优缺点、证券示例、常与谁组合。
> 方法选择的固化映射见 `mapping-matrix.md`；本目录用于向人解释方法的执行细节。

---

## 1. 等价类划分（Equivalence Class Partitioning）
- **定位**：输入域分域的骨架方法，第一层必用。
- **适用**：任何带输入的功能；输入可划分为"处理行为相同"的若干类。
- **步骤**：① 识别输入域 → ② 划分有效等价类与无效等价类 → ③ 每类至少选 1 个代表值 → ④ 无效类逐类覆盖（一次只违反一个约束，避免错误掩盖）。
- **产出**：等价类表（编号/描述/有效或无效/代表值）。
- **优点**：用最少用例覆盖最大输入域；是所有方法的骨架。
- **缺点**：单独使用测不到边界和组合；类划分依赖经验。
- **证券示例**：委托价格有效类 [0.01, 涨停价]；无效类 {≤0}、{>涨停价}、{非数字}。
- **组合**：打底后接边界值（加密）、判定表（组合）。

## 2. 边界值分析（Boundary Value Analysis）
- **定位**：边界缺陷的收割机，缺陷 70% 以上藏在边界附近。
- **适用**：有范围、有精度、有步长、有极值、有容量阈值的输入/输出。
- **步骤**：① 确定每个边界 → ② 取上点（边界上）、离点（刚好越界）、内点（边界内侧）→ ③ 单边界逐个突破（一次只压一个边界）→ ④ 补充 0/负数/空/超长/溢出等特殊值。
- **产出**：边界数据矩阵。
- **优点**：性价比最高的单方法；机械可执行。
- **缺点**：不管输入之间的组合。
- **证券示例**：100 股整数倍 → 99/100/101；单笔上限 100 万股 → 100万/100万+100。
- **组合**：等价类之后加密；判定表确定"哪个条件要测边界"后落地。

## 3. 判定表法（Decision Table Testing）
- **定位**：条件组合完整性的证明工具。
- **适用**：条件数 2~5、结果唯一、条件组合决定动作。
- **步骤**：① 列条件桩与动作桩 → ② 枚举 2^n 组合 → ③ 标记每组合的动作 → ④ 合并无关项化简 → ⑤ 每条规则 ≥ 1 条用例 + 冲突检测用例。
- **产出**：判定表（规则列 × 条件/动作行）+ 化简记录。
- **优点**：组合无遗漏、可评审、可直接转用例。
- **缺点**：条件数 > 5 组合爆炸；管不了时序。
- **证券示例**：可撤单判定（订单状态 × 时段 × 板块 × 是否成交 → 可撤/不可撤）。
- **组合**：条件有约束先因果图化简；边界值补每个条件的取值边界。

## 4. 因果图法（Cause-Effect Graphing）
- **定位**：条件约束的化简器，判定表的前置。
- **适用**：条件间存在互斥（E）、包含（I）、唯一（O）、要求（R）、屏蔽（M）关系。
- **步骤**：① 列原因与结果 → ② 画因果图（与/或/非）→ ③ 标注约束关系 → ④ 转判定表 → ⑤ 剔除不可能组合。
- **产出**：因果图 + 化简后的判定表。
- **优点**：避免 2^n 中混入不可能组合；暴露规则本身的矛盾。
- **缺点**：图复杂后可读性差；学习成本高于判定表。
- **证券示例**：市价委托（无价格字段）与保护限价（科创板必填）的约束关系。
- **组合**：几乎总是与判定表连用。

## 5. 状态迁移测试（State Transition Testing）
- **定位**：生命周期的覆盖器。
- **适用**：对象有状态、状态 ≥ 3、同一操作在不同状态结果不同。
- **步骤**：① 建状态-事件矩阵 → ② 覆盖全部合法迁移 → ③ 设计非法迁移用例（≥ 3 条，绕过前端构造）→ ④ 检查不可达状态与死锁状态。
- **产出**：状态-事件矩阵 + 迁移路径用例集。
- **优点**：时序与顺序敏感缺陷的克星。
- **缺点**：状态多时矩阵大；不覆盖状态内的数据正确性。
- **证券示例**：委托单 待报→已报→部成→已成/已撤/废单；非法迁移 已成→撤单。
- **组合**：与边界值叠加（部成后余量重算）；与场景法叠加（迁移的业务上下文）。

## 6. 场景法（Scenario / Use Case Testing）
- **定位**：业务走法的地图，用户视角。
- **适用**：端到端流程、存在多种走法与中断恢复。
- **步骤**：① 画基本流 → ② 列备选流 → ③ 穷举异常流（每个环节问"这里失败会怎样"）→ ④ 每个场景 ≥ 1 条用例 → ⑤ 优先级：异常流 ≥ 备选流 ≥ 基本流。
- **产出**：场景清单（基本流/备选流/异常流）+ 场景用例。
- **优点**：最贴近真实使用；发现集成与流程级缺陷。
- **缺点**：不擅长单点深度；场景数量靠经验控制。
- **证券示例**：开户→测评→转账→委托→成交→清算→对账，异常流含测评不通过/转账失败/废单/清算延迟。
- **组合**：错误推测补流外盲区；状态迁移补跨系统状态对齐。

## 7. 正交试验设计（Orthogonal Array Testing）
- **定位**：组合爆炸的降维器，主要效应 + 均匀分散。
- **适用**：多参数多取值、组合 > 20、交互弱、参数取值数较整齐。
- **步骤**：① 列因子与水平 → ② 估算笛卡尔积 → ③ 选正交表（L9(3^4)/L16(4^5)/L18…）→ ④ 实例化参数 → ⑤ 给出覆盖率与损失说明。
- **产出**：正交表实例化用例集 + 损失说明。
- **优点**：用例数大幅下降且分布均匀；有数学依据。
- **缺点**：参数水平数不整齐时选表困难；高阶交互覆盖不到。
- **证券示例**：委托类型×板块×时段 72 组合 → L18。
- **组合**：与 Pairwise 互补（正交管均匀、Pairwise 管两两全覆盖）。

## 8. 成对测试（Pairwise / All-Pairs Testing）
- **定位**：交互对的压缩器，两两交互为主的超大组合。
- **适用**：参数多（≥ 4）、组合数百以上、缺陷多由两参数交互触发。
- **步骤**：① 列参数与取值 → ② 生成覆盖全部参数对的最小用例集（工具：PICT/ACTS/allpairspy）→ ③ 标注每用例覆盖的参数对 → ④ 给出两两覆盖率。
- **产出**：Pairwise 用例集 + 参数对覆盖率报告。
- **优点**：通常比正交更省用例；两两覆盖 100% 可证明。
- **缺点**：三因子以上交互无保证；需工具生成。
- **证券示例**：机型×OS×网络×语言 兼容性矩阵。
- **组合**：与正交互补；关键三参数组合可人工补充专项。

## 9. 分类树法（Classification Tree Method）
- **定位**：层级参数的组合器，等价类与组合方法的桥梁。
- **适用**：参数有层级/树形结构，每层可划等价类，类之间需要组合。
- **步骤**：① 按方面（aspect）分层 → ② 每层划分类 → ③ 在组合表中标点选类 → ④ 每行一个用例。
- **产出**：分类树 + 组合表。
- **优点**：结构清晰，适合参数间有包含关系的场景。
- **缺点**：层级深时组合表膨胀。
- **证券示例**：账户（个人/机构）→ 板块（沪深/科创/创业/北交）→ 委托方式 的树形组合。
- **组合**：与判定表/正交接力（分类树确定取值，正交/Pairwise 降维）。

## 10. 错误推测法（Error Guessing）
- **定位**：历史缺陷的反向利用，经验驱动的补漏层。
- **适用**：无明确规则区域、历史缺陷高发区、所有测试点的第四层。
- **步骤**：① 翻历史缺陷库同类功能 → ② 列"通常会错什么"清单 → ③ 逐条构造反向用例（幂等/并发/超时/重放/非法时序/文案/降级）→ ④ 归入用例集并标注来源缺陷。
- **产出**：缺陷清单 → 反向用例。
- **优点**：命中率高（缺陷有聚集性）；覆盖系统性方法覆盖不到的区域。
- **缺点**：依赖经验与缺陷库质量；不能作为唯一方法。
- **证券示例**：重复提交委托、撤单与成交竞态、全角数字输入、超长名称溢出。
- **组合**：作为所有测试点的第四层兜底。

## 11. 语法测试（Syntax Testing）
- **定位**：形式文法的正反例生成器。
- **适用**：报文、协议、文件格式、正则约束字段。
- **步骤**：① 拿语法规范（BNF/Schema/正则）→ ② 每条规则构造正例 → ③ 每条规则构造违反用例（缺字段/错类型/错顺序/超长/非法字符）→ ④ 检查拒绝行为与错误定位。
- **产出**：语法正反例用例集。
- **优点**：机械可执行；协议类缺陷覆盖全。
- **缺点**：只管格式不管语义。
- **证券示例**：柜台报文字段校验、批量委托文件导入、FIX 报文。
- **组合**：字段取值域交给等价类；语义规则交给判定表。

## 12. 随机测试（Random Testing）
- **定位**：超大输入域的统计覆盖。
- **适用**：输入域不可枚举、需要稳定性/健壮性验证。
- **步骤**：① 定义输入分布 → ② 固定随机种子 → ③ 分层抽样生成数据 → ④ 失败样本归档进回归集。
- **产出**：抽样方案 + 种子 + 失败样本库。
- **优点**：成本低的广撒网；能发现意料之外的组合。
- **缺点**：覆盖率不可证明；不设种子无法复现。
- **证券示例**：行情回放压测、风控规则 fuzz。
- **组合**：先等价类分层再在层内随机，避免分布偏斜。

## 13. 探索性测试（Exploratory Testing）
- **定位**：无规则区域的学习与发现。
- **适用**：需求缺失、新功能认知、规则之外的盲区。
- **步骤**：① 定 charter（本次探索目标与时间盒）→ ② 边学习边设计边执行 → ③ 记录发现与新测试点 → ④ 有价值发现固化为正式用例。
- **产出**：charter 记录 + 新发现清单 + 固化用例。
- **优点**：发现"不知道自己不知道"的缺陷。
- **缺点**：不可重复、不可度量、依赖个人能力。
- **证券示例**：新版交易终端的交互探索；异常提示体系的梳理。
- **组合**：错误推测法定方向，探索性测试做执行。

## 14. 规格说明/检查表法（Specification-based Checklist）
- **定位**：需求条目的核对器，防条目级遗漏。
- **适用**：任何需求文档的验收核对；评审检查单。
- **步骤**：① 把需求拆成逐条可勾选项 → ② 每条对应至少 1 条用例 → ③ 双向追溯（需求→用例、用例→需求）→ ④ 无对应用例的条目列入风险清单。
- **产出**：需求-用例追溯矩阵。
- **优点**：保证需求覆盖率的底线；评审友好。
- **缺点**：只保证"有"，不保证"深"。
- **证券示例**：交易所业务规则逐条核对清单。
- **组合**：作为所有方法产出后的总核对层（对应质量闸门 ①）。
