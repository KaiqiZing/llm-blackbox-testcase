# Prompt 0 · 素材清点（不可跳过）

> **输入**：需求素材（正文 + 图片 + 附件），以及 `scripts/extract_images.py` 产出的 `manifest.json`。
> **产出**：`asset-inventory.json` —— 素材单元清单 + 文本→图片锚点映射 + 缺口清单。
>
> 这一步不做需求拆解，**只做清点与锚定**。它的作用是保证后面 Prompt 1 拆解时，
> 「如图所示」不再是一句空话，而是能落到具体图片编号与提取元素上。
>
> 规范依据：`references/image-extraction.md`（§二 锚点映射、§三 八类必提元素、§四 回填方式）。
> **本步产出是 Prompt 1 的必选输入**。没有 `asset-inventory.json` 就进第 1 步，等于放弃图片需求源。

```text
【输入·素材清单（由 extract_images.py 产出）】
{{粘贴 manifest.json 内容；若无图片，填 []}}

【输入·需求正文】
{{粘贴需求文档正文（可保留段落序号）}}

【输入·图片内容】
{{逐张描述已提取的图片；每张图的描述必须按下列八类清单逐条写，不要概述}}
{{若图片已在对话上下文中，直接说明「见上文第 N 张图」}}

【任务】对需求素材做清点，产出素材清单、文本→图片锚点映射、缺口清单。只做清点，不拆需求。

【约束】
1. 每个素材单元（文本段 / 图片 / 附件）都要登记，不得遗漏；图片编号沿用 manifest.json 的 img-N；
2. 正文中出现下列措辞的段落，必须在 image_refs 里登记，并解析出指向哪张图：
   如图所示 / 如下图 / 见下图 / 如左图所示 / 如图 1 所示 / 图 3-1 所示 / 按下图 / 如下截图 / 如上图 / 如下表 / 见附表 / 界面如下 / 参考下图 / 参照下列图；
   以及「无措辞但强依赖」情形：段落以 字段/按钮/列/查询条件/操作 为主语列举，但列举项只有 1~2 个
   （列举必然不全，完整清单在图里）；
3. 解析不出指向哪张图的引用，不得跳过，必须写入 gaps，类型为「硬缺口」；
4. 图片内容清点必须按八类清单逐条进行：字段名+必输标记 / 按钮+位置 / 列表列名 /
   查询条件 / 分页参数 / 状态列 / 弹窗文案 / 校验提示；不属于该图的类别写「—」；
5. 看不清的元素写「[图不清] 疑似：xxx」，不得猜测；
6. 图片可见但未被任何文本段落引用 → 写入 gaps，类型「有图无引用」；
7. 正文与图片矛盾时 → 写入 gaps，类型「图文冲突」，不得自行取舍；
8. 不做任何业务规则推断，只描述「素材里有什么」。

【输出】严格 JSON，不要额外解释：
{
  "assets": [
    {
      "id": "A1",
      "类型": "文本段|图片|附件",
      "来源": "英文研报运营.docx|对话粘贴|剪贴板截图",
      "位置": "4.1 新增英文研报 / word/media/image2.png / 第3段",
      "是否需提取": true,
      "说明": "图片；对应新增弹窗表单"
    }
  ],
  "image_refs": [
    {
      "引用文本段": "b. 字段如图所示",
      "所在章节": "4.1 新增英文研报",
      "引用措辞": "如图所示",
      "指向图片": "img-2",
      "锚定依据": "顺序对齐 + 语义匹配（表单类截图，与『字段』吻合）",
      "置信度": "高|中|低"
    }
  ],
  "image_elements": [
    {
      "图片编号": "img-2",
      "界面名": "新增英文研报",
      "字段": ["标题*（文本输入，必输）", "摘要*（多行文本，必输）"],
      "按钮": ["取消（弹窗底部，次按钮）", "保存（弹窗底部，主按钮）", "直接上架（弹窗底部，主按钮）"],
      "列表列": ["—"],
      "查询条件": ["—"],
      "分页参数": ["—"],
      "状态列": ["—"],
      "弹窗文案": ["[图不清] 疑似：新增英文研报"],
      "校验提示": ["[图不清] 需人工补录"]
    }
  ],
  "gaps": [
    {
      "类型": "硬缺口|有图无引用|图文冲突|锚点存疑|提取失败",
      "位置": "3.2 上架流程",
      "描述": "正文写『含批量』，已上架界面截图只有单条下架按钮",
      "处置建议": "拆两条需求点，均标待确认，交业务方裁决"
    }
  ]
}
```

## 失败信号

- `image_refs` 为空，但正文含「如图所示」类措辞 → 锚点映射未做，打回。
- `image_elements[].按钮` 全为「—」，但图明显是界面截图 → 没真正看图，打回。
- 某一类元素写成「若干」「一些」「等」→ 概述代替了清点，打回。
- `gaps` 里出现「提取失败」，但后续未声明证据降级 → 静默降级，打回交付。
- 直接跳到业务规则推断（写出「校验通过后状态变已上架」）→ 越界，本步只清点素材。

## 与后续步骤的接口

| 本步产出字段 | 被谁消费 | 消费方式 |
|---|---|---|
| `image_refs[]` | Prompt 1 | 决定需求点的 `图片依据.图号` 与 `引用措辞` |
| `image_elements[]` | Prompt 1 | 直接作为 `图片依据.提取元素` 的原料（逐条搬，不要压缩） |
| `gaps[]` 中「硬缺口/图文冲突」 | Prompt 1 + 质量闸门⑨ | 对应需求点必须标 `待确认: true` |
| `gaps[]` 中「有图无引用」 | 人工复核 | 报告 §0 需列出，逐条给出是否漏需求的判断 |
| `assets[]` | 交付说明 | 报告开头声明本次素材构成与提取完整性 |

## 机械校验

```bash
python3 scripts/validate-output.py asset-inventory.json --stage inventory --manifest ./assets/manifest.json
```

检查内容：素材单元登记完整性、锚点图号合法性（img-N 且存在于 manifest）、
八类元素清点完整性（每张图 8 类键齐全、总条数 ≥ 2、无「若干/一些」概述词）、
manifest 全图是否都有清点、硬性缺口统计。
